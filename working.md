# DropBox-lite: Architecture & Services Guide

> A comprehensive reference document detailing all cloud services, architecture diagrams, design decisions, and workflows for DropBox-lite.

---

## 1. Executive Summary & Purpose

DropBox-lite is a high-performance, serverless temporary file-sharing web application inspired by WeTransfer. It provides private, ephemeral file transfers with automatic time-to-live (TTL) expiration, direct browser-to-cloud uploads, and zero persistent infrastructure maintenance.

The core architectural constraint is **100% pure serverless operation**: NO EC2 instances, NO ECS containers, NO always-on databases, and NO traditional backend servers. When the application is idle, resource utilization and operating costs are exactly **$0.00**.

## 3. Core AWS Services Used & Exact Purpose

### 1. AWS Lambda (Serverless Compute)
- **Purpose**: Executes backend business logic on-demand with zero idle servers.
- **Runtime & Architecture**: Node.js 20 on `arm64` (AWS Graviton2 processors) for superior energy efficiency, 20% lower cost, and lower latency.
- **Connectivity**: Exposed directly via **Lambda Function URLs** with built-in CORS configuration, eliminating the cost and overhead of an API Gateway.
- **Security**: Strictly scoped IAM execution roles granted only the minimum required actions per function.

### 2. Amazon DynamoDB (Metadata & TTL Engine)
- **Purpose**: Ultra-fast, single-digit millisecond latency key-value data store for file records.
- **Billing Mode**: `PAY_PER_REQUEST` (On-Demand), incurring zero charges when not queried.
- **Attributes Stored**: `fileId` (Partition Key), `fileName`, `size`, `contentType`, `s3Key`, `expiresAt` (epoch seconds TTL), `deleteToken` (SHA-256 hash), `downloads` (atomic counter), and `createdAt`.
- **Automatic Cleanup**: DynamoDB TTL continuously identifies and expires records once `expiresAt` passes.

### 3. Amazon S3 (Private Storage Bucket)
- **Purpose**: Secure, durable object repository for user-uploaded files.
- **Direct Uploads**: Employs `@aws-sdk/s3-presigned-post` with a `content-length-range` condition enforcing the 50 MB limit directly at the S3 API boundary.
- **Security**: All public access blocked (`BlockPublicAcls`, `BlockPublicPolicy`, `IgnorePublicAcls`, `RestrictPublicBuckets`). Server-Side Encryption enabled (`AES256`).
- **Safety Net**: Configured with an S3 Lifecycle Rule that permanently purges any object older than 1 day.

### 4. Amazon S3 (Static Website Hosting Bucket)
- **Purpose**: Hosts the compiled static assets (`index.html`, `f/index.html`, `404.html`, and `/_next/static/*`) generated by Next.js `output: 'export'`.
- **Reliability**: Configured with bucket website configuration and public read policy for high availability without managing a web server.

### 5. AWS CloudFront CDN & OAC (Optional / Upgrade)
- **Purpose**: Global low-latency Content Delivery Network.
- **Capabilities**: Delivers free SSL/TLS HTTPS encryption, Gzip/Brotli edge compression, and secures the origin via Origin Access Control (OAC).

### 6. AWS CloudFormation & AWS SAM (Infrastructure as Code)
- **Purpose**: Defines, provisions, and manages all cloud infrastructure in a single declarative `template.yaml`.
- **Benefits**: Eliminates manual console clicks, ensures reproducibility, and enables one-command CI/CD deployment via `deploy.ps1`.

### 7. esbuild Bundler
- **Purpose**: High-speed JavaScript bundler that packages each Lambda handler into a single optimized bundle.
- **Optimization**: Marks `@aws-sdk/*` as external to utilize the native AWS SDK v3 built into the Lambda Node.js 20 runtime, keeping bundle sizes under 2 KB.

### 8. Next.js 14 App Router & Tailwind CSS (Frontend)
- **Purpose**: Mobile-first, responsive, lightweight user interface.
- **Architecture**: Configured with `output: 'export'` (pure static HTML/CSS/JS export). NO SSR, NO server actions, NO API routes.
- **Features**: Drag-and-drop file upload, XMLHttpRequest progress tracking, live countdown timer, and cross-browser clipboard fallback supporting both HTTP and HTTPS contexts.

## 4. Lambda Function Breakdown

| Lambda Function | HTTP Method | Trigger / URL | Primary Responsibility |
| :--- | :--- | :--- | :--- |
| **`createUpload`** | `POST` | `/` | Sanitizes filenames, blocks dangerous extensions (`.exe, .bat, .cmd, .scr, .js, .vbs, .ps1`), validates 50MB limit, hashes delete token, writes DynamoDB item, generates S3 presigned POST. |
| **`getFile`** | `GET` | `/?id=XXXX` | Validates in-code TTL (`expiresAt <= now` returns 410 Gone), atomically increments download counter (`ADD downloads :inc`), generates 60s presigned GET URL with attachment headers. |
| **`deleteFile`** | `POST` / `DELETE` | `/` | Authenticates secret `deleteToken` using `crypto.timingSafeEqual` SHA-256 comparison, permanently deletes file from S3 bucket, removes record from DynamoDB. |

## 5. Security & Cost Optimization Highlights

1. **Zero-Cost Idle Footprint**: 100% serverless design incurs $0.00 when traffic is zero. All storage automatically self-cleans within 24 hours.
2. **Direct Client-to-S3 Streaming**: Raw file bytes never pass through Lambda compute, keeping memory low and avoiding timeout/concurrency bottlenecks.
3. **Least-Privilege IAM**: Each Lambda is restricted to the exact actions needed (`s3:PutObject` for upload, `s3:GetObject` for download, `s3:DeleteObject` for delete).
4. **Resilient Clipboard API**: Features dual-mode clipboard support (`navigator.clipboard` for HTTPS with fallback to `document.execCommand` for HTTP).
